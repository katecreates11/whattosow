## Dreamt connections

**1. The crew reads taste reliably and reads board state unreliably, and
those have always been scored as one thing until this week.** The 25
October run's duplicate pitches weren't badly judged — they were
calculator-DNA-shaped, plan-and-order-now-shaped, exactly the moves this
file says Kate likes. What failed was knowing those moves had already
been made. Splitting "does it read taste" from "does it read board state"
as two separate confidence entries (done in wisdom.md §1 this week) should
make future weeks' scoring sharper — a relapse into stale `main` is a
board-state failure, not evidence the taste rules themselves need
revising.

**2. Two silent channels, found in the same week, are more informative
together than either alone.** A stuck PR nobody reviews and a stuck draft
nobody opens are structurally the same shape: something sits waiting for
a human glance that nothing currently prompts. Worth treating "does
anything in this pipeline generate an actual notification Kate would see
without going looking" as its own standing question, not two unrelated
findings.

**3. The bare-root family (ten cards) and the rhubarb-forcing repeat
(three independent pitches of the same piece) are the same underlying
event at two different scales.** Both are the write-to-main bug's real
cost made visible: not "ideas go missing" (they don't — every one
eventually gets recovered) but "the same work gets re-pitched by agents
who can't see each other," which burns Forager runs on content that
already exists rather than new ground. The backlog's size is a symptom;
this is closer to the disease.

Seventeen drafts, each one longer than the last as the backlog grew,
apparently unopened. This week's draft (see Gmail) does the opposite:
one line naming the single easiest action (one comment unlocks PR #3),

**What if the next Forager run is deliberately *not* named this time, as
the control this experiment was missing?** Last week named a run and it
didn't respond; the week before that, an unnamed run (4 October) came
back clean on its own. Two data points on "named" (1 hit, 1 miss) and at
least one on "unnamed, clean anyway" suggest the variable that matters
might be something else entirely — which prior branch happened to be
easiest to find — not whether this file spoke to it directly. Worth
letting the next few runs go unremarked-on and just watching what they do
with the base, rather than running another named experiment on top of a
pattern that's still this noisy.
