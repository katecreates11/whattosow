## Dreamt connections

**1. Two silent "fix the words" experiments have now both failed in the
same shape, and the lesson is to stop running that kind of experiment.**
Naming a run by date, and shortening a draft's wording, are both attempts
to fix a human-attention problem from inside the artifact the human isn't
opening. Both produced a clean null result. The next useful experiment,
if there is one, is probably not a third wording change but something
structural — which is why card 85 (point future runs at the latest dream
branch by configuration, not by asking nicely in a memory file) is framed
as a question for whoever sets up these routines, not a fix this memory
can write its own way out of.

**2. The bare-root family went a full week without a new duplicate for
the first time in six weeks, in the same week the Forager had its
cleanest run ever.** One data point, and it could easily be coincidence —
the 1 November run simply pitched into unrelated ground (fruit pruning,
greenhouse insulation, wet-weather jobs) rather than deliberately avoiding
bare-root. But it's consistent with dreamt connection #1 from two weeks
ago: a run that can see the real board state stops re-pitching into
families that board state would have shown it were already full.

**3. Rhubarb forcing's fourth convergence is the clearest evidence yet
that "independently converged" is itself a strong taste signal, not just
a tie-breaker.** Three Forager pitches and now one SEO Watchdog finding,
from three different evidence bases, have landed on the same page
section. If a Bench session ever happens and there's only time for one
card, wisdom.md now says plainly which one that should be (card 49, via
card 84's flag) — not by guessing at Kate's taste, but by the weight of
how many independent angles keep finding the same gap.

**4. The Sarah Raven "zero results" finding and the four confirmed-dead
links are the same underlying fragility at two different depths, and
neither has had a real browser pointed at it in over twelve weeks of
"dead link" cycles.** Every prior cycle has been a plain `curl` or fetch
check, repeatedly confirming the same four SKUs are dead and now finding
a possible fifth, systemic issue on top — but no one has opened the site
in an actual browser to settle either question in three months. The
finding keeps getting re-confirmed instead of fixed.
