# The SEO Watchdog — 8 July 2026

First baseline report (no prior week to diff against). Repo + live-site audit,
no Search Console API yet — indexing checks below are approximate `site:`
searches and should be sharpened with GSC once it's connected.

## FIX NOW

Ordered by impact. Each names the exact file/page and the exact change.

### 1. `/grow-your-christmas-dinner` has zero internal links — it's a true orphan
`grep -rn "grow-your-christmas-dinner" src/` matches only the page's own file
and `sitemap.ts`. No nav item, no footer link, no homepage link, no guide or
crop cross-link points to it anywhere. It's in the sitemap at `priority: 0.8`,
`changeFrequency: "weekly"`, shipped 7 July — currently invisible to both
readers and crawlers except by typing the URL. **Fix:** add at least one link
from a page that already gets traffic — the natural homes are `/guides` (a
seasonal-doors slot), the footer's seasonal-whisper line, or a cross-link from
`/guides/growing-root-vegetables` and `/guides/preparing-your-plot-for-winter`
(parsnips, sprouts, leeks — the Christmas-dinner crops). Do this now, months
before December search demand — a page needs lead time to earn authority.

### 2. Homepage renders two `<h1>` elements
`src/app/page.tsx` lines 265 and 295: one `<h1>` inside a `sm:hidden` mobile
block, one inside a `hidden sm:flex` desktop block, both reading "Know exactly
what to plant, right now." CSS only toggles *visibility*; both land in the
rendered HTML, so the homepage — the single most important page on the site —
has a duplicate-H1 issue. **Fix:** one semantic `<h1>`, toggle styling with
`block`/`hidden` on that single element instead of two separate elements, or
demote the non-primary copy to a `<p aria-hidden>`.

### 3. 181 variety pages are reachable only through their parent crop page
Confirmed by tracing every internal link: `/crops` index links to crop pages
only (never varieties), the homepage's `FeaturedVariety` component
(`src/components/FeaturedVariety.tsx:76`) showcases a different variety every
week but its only outbound link is the **affiliate seed-supplier URL** — it
never links to the variety's own `/crops/[slug]/[variety]` page. That's a
missed internal link on the homepage every single week. **Fix:** add a second
link from `FeaturedVariety` to the variety's own page (keep the affiliate link
too — they serve different jobs).

### 4. 24 auto-generated monthly blog posts share one description sentence
`src/data/blog-posts.ts`'s `generateDescription()` produces the identical
pattern for all 24 (Jan 2026–Dec 2027) posts: *"What to sow in {Month} in the
UK — {N} crops to start this month, with varieties, timing, and honest growing
tips."* Only the month name and a crop count change. This is a textbook
duplicate/thin-description pattern across two dozen indexed URLs. Per
`docs/CUT_LIST.md` §4 this is already slated for a bigger move (fold into
`/sow/[month]`, stop future auto-publishes) — flagging here because that's now
a live SEO liability, not just an editorial one, and worth prioritising before
more of the 24 get crawled and cached with this description.

### 5. Titles and descriptions run long across nearly every guide page
All 29 static guides carry a `keywords` array and a self-referencing canonical
(fine), but titles and descriptions are consistently oversized and will
truncate in Google's SERP snippet:
- **Titles over 60 characters** (truncates): 20 of 29 guides, worst offenders
  `/guides/dealing-with-the-glut` (91 chars — longest on the site, and it's
  brand new, published 5 July),
  `/guides/overwintering-broad-beans-and-peas` (85),
  `/guides/protecting-vegetables-from-frost` (83),
  `/guides/companion-planting-chart` (82).
- **Descriptions over 160 characters** (truncates): nearly all 29, worst
  `/guides/growing-root-vegetables` (213), `/guides/watering-while-away` (214
  — also brand new, 5 July), `/guides/growing-winter-salad-leaves` (210),
  `/guides/protecting-vegetables-from-frost` (209).
- Non-guide pages also affected: `/guides/growing-tomatoes-outdoors-vs-greenhouse`
  and 2 of the 3 crop "playbook" titles (`tomatoes`, `carrots`, `courgettes`
  in `src/app/crops/[slug]/page.tsx`) run 77–91 chars; `/sow` description
  (171), `/bed-planner` description (215), `/frost-map` (164),
  `/longest-day` (168), `/grow-your-christmas-dinner` title (67) and
  description (168) are all over target.
- **Fix:** tighten titles to ~50–60 chars and descriptions to ~140–160 chars,
  front-loading the actual query. Start with the two brand-new guides
  (`dealing-with-the-glut`, `watering-while-away`) since they haven't
  accumulated any cached snippet yet — cheapest fix, freshest page.

### 6. `/crops`, `/sow`, `/grow`, `/harvest` carry zero structured data
Not even `BreadcrumbList`. These are major hub pages — `/crops` is the
48-item field-guide index. **Fix:** add `BreadcrumbList` to all four at
minimum; `/crops` is also a good `ItemList`/`CollectionPage` candidate given
its numbered-index structure.

### 7. Article/HowTo schema is inconsistent across guides using the identical template
10 of 29 guides use the same `GuideHero` editorial template as the other 19
(several explicitly declare `openGraph.type: "article"`) but emit only
`FAQPage` + `BreadcrumbList` — no `Article`: `growing-fruit`, `soil`,
`seed-starting`, `pests`, `beginners`, `watering`, `crop-rotation`,
`composting`, `seed-starting-kit`, `allotment-essentials`. Two of those
(`seed-starting`, `crop-rotation`) render numbered step-by-step content via
`StepList`/`ProcessDiagram` components but carry no `HowTo` schema either,
despite being exactly the "numbered steps" page type the schema exists for.
**Fix:** bring these 10 up to the same `Article` (+`HowTo` for the two
step-driven ones) coverage the other 19 already have — should be a
copy-the-pattern job, not new design work.

### 8. Crop-page `HowTo` schema has drifted from the visible content
For the 3 crops with full playbooks (`tomatoes`, `carrots`, `courgettes` —
`src/data/crop-playbooks.ts`), the page visibly renders a richer numbered
"growing, step by step" section from `playbook.care` (`src/app/crops/[slug]/page.tsx`
line ~641), but the `HowTo` JSON-LD (line ~470) is still built from the
generic `sowIndoorsWeeks`/`directSowWeeks`/`plantOutWeeks`/`harvestWeeks`
fields shared by all 48 crops. The schema no longer matches what a reader (or
a rich-results crawler) actually sees on the 3 highest-effort crop pages on
the site. **Fix:** for crops with a playbook, build `HowTo.step` from
`playbook.care` instead of the generic date fields.

### 9. `/guides/tomato-blight` is the weakest-linked guide on the site
No related-guides block (every other guide has one), no `backLink` prop back
to `/guides` (it's the only guide using bare `<Header />`), and its only
outbound links are `/crops/tomatoes`, `/crops/potatoes`, `/blight-watch`. It's
still inbound-linked from `/guides` index and one other guide, so not orphaned
— but it's a dead end for a reader who lands there, despite `priority: 0.8` /
`changeFrequency: "daily"` in the sitemap (the highest-priority guide on the
site by that metric). **Fix:** add the standard related-guides block and
`backLink`.

### 10. `keywords` meta arrays are still present in ~57 locations
Per `docs/CUT_LIST.md` §4 ("Google has ignored the keywords tag since 2009 …
stop adding them"), every static page, all 29 guides, and 5 dynamic templates
(`crops/[slug]`, `sow/[month]`, `sow-in/[city]`, `blog/[slug]`,
`guides/companion-planting/[topic]`) still set one. Harmless but cargo-cult —
lowest priority on this list, worth a single sweep when someone's next in
those files rather than a dedicated pass.

### 11. `/lucky-dip` self-canonicalizes to `/my-garden` but renders different metadata
`src/app/lucky-dip/page.tsx` sets `alternates.canonical: "/my-garden"` and
`openGraph.url: "/my-garden"`, but keeps its own distinct title/description
and both pages render the same `<ReactGarden />` component. This is confusing
for crawlers (a page telling Google "the *real* URL is elsewhere" while still
presenting itself with different on-page metadata). This is the same page
`docs/CUT_LIST.md` §1 and `docs/NEXT_PHASES.md` §5.1 flag for a **blocked**
merge decision — not proposing that here, just flagging that the current
half-state (self-canonicalized but not merged) is worse for SEO than either
finished state would be. Needs Kate's yes per NEXT_PHASES before any code change.

## OPPORTUNITIES

### 1. "How to save tomato seeds" — no coverage anywhere on the site
Grepped the full codebase for seed-saving content: zero results. This is a
real, evergreen UK query, and it's timely right now — first ripe tomatoes are
weeks away, and gardeners search this as fruit starts colouring in
August. The site already has deep tomato content (a playbook, a
outdoors-vs-greenhouse guide, a blight guide, 20+ tomato varieties) but
nothing on saving seed from this year's crop for next year. **Suggested
placement:** a short section added to
`/guides/growing-tomatoes-outdoors-vs-greenhouse` (cheapest, reuses existing
traffic) or, if it merits its own page, cross-link it from the tomato crop
page and from tomato variety pages (open-pollinated ones especially, where
seed-saving actually works).

### 2. `/grow-your-christmas-dinner` — near-miss, not a coverage gap
Already covered in Fix Now #1/indexing above, repeating here because it's
also the strongest *seasonal* opportunity this week in the other direction:
the page exists, is well-scoped, and Christmas-dinner-growing is a real
December query cluster — but a page published 7 July with zero internal links
and no index presence yet has five months to earn authority before the demand
peak, and right now it's using none of that runway. Link it and request
indexing this week, not in November.
