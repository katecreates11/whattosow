# The SEO Watchdog — weekly SEO health

**Date:** 28 July 2026
**Scope:** repo audit + live site + web search. No Google Search Console access yet — every indexing claim below is approximate; a GSC connection would sharpen all of it (see note at the end).

## FIX NOW

Ordered by how many pages each touches, most impactful first. All are on-page/technical — no content rewrites recommended here beyond what's needed to fix the bug.

### 1. All 51 `/sow-in/[city]` pages will show a frozen month/year forever
`src/app/sow-in/[city]/page.tsx:46-47` builds the `<title>` and meta description from `new Date()` **at build time** ("What to Sow in {city} — {monthName} {year} Sowing Guide"). Unlike `src/app/crops/[slug]/page.tsx:408`, which sets `export const revalidate = 86400`, the city template has **no revalidate export and no dynamic setting** — it's fully static. Once deployed, all 51 pages will keep showing whatever month/year they were built in (currently "July 2026") until the next full site rebuild, drifting further wrong every week there isn't one. This is a real bug, not just a style nit — a page confidently telling a reader in December it's a "July sowing guide" is a trust problem as much as an SEO one.
**Fix:** add `export const revalidate` to `src/app/sow-in/[city]/page.tsx` matching the crop-page pattern (daily or monthly), or compute the date at request time.

### 2. FAQPage structured data is missing from 45 of 48 crop pages
`src/app/crops/[slug]/page.tsx:477-487` only emits `FAQPage` JSON-LD when a `crop-playbooks.ts` entry exists — currently just tomatoes, carrots and courgettes. The other 45 crop pages carry real sowing/care/problem Q&A content but no schema to make it eligible for rich results.
**Fix:** either extend the FAQ schema to pull from whatever Q&A content already exists on the generic crop template (not just playbook crops), or scope the playbook rollout (already planned per `docs/CADENCE.md`/NEXT_PHASES) with the SEO win in mind.

### 3. Crop page meta descriptions run over Google's ~160-character display limit
`src/app/crops/[slug]/page.tsx:430-432`. Two templates, both affected:
- The generic (45-crop) fallback exceeds 160 chars for longer names — "Potatoes (maincrop)" → 168 chars, "Potatoes (early)" → 162, "Brussels sprouts" → 162.
- The playbook description is worse: tomatoes 176, carrots 175, courgettes 178 chars.
**Fix:** trim both templates to fit comfortably under 155-160 chars including the crop name.

### 4. Playbook crop page titles run long enough to truncate in search results
`src/app/crops/[slug]/page.tsx:427-429` — "How to Grow {name} in the UK — When to Plant, Care & Problems | What To Sow" is 77-94 chars for tomatoes/carrots/courgettes (Google typically shows ~60). The other 45 crops use a shorter, fine template ("When to Plant {name} in the UK — What To Sow", 46-63 chars) — worth matching the playbook titles to roughly the same length.

### 5. Variety page titles are awkward for compound crop names
`src/app/crops/[slug]/[variety]/page.tsx:42` — most variety titles are fine (51-88 chars sampled), but compound names read oddly and run long, e.g. "Purple Sprouting Broccoli Early purple sprouting broccoli — how to grow it | What To Sow" (88 chars, crop name repeated in different case). Lower priority than 1-4, but a quick template tidy (don't repeat the crop name if the variety name already contains it) would help 181 pages read better in results.

### 6. `keywords` meta arrays are still being added — 54 files
Per `docs/CUT_LIST.md` §4, Google has ignored the `keywords` tag since 2009 and new pages should stop adding it. It's still present in 54 files, including every one of the 30 files under `src/app/guides/**`, `layout.tsx:32`, `crops/[slug]/page.tsx:433`, `sow/[month]/page.tsx:39`, `sow-in/[city]/page.tsx:48`, and several standalone pages (`blight-watch`, `calendar`, `frost-map`, `harvest-planner`, `longest-day`, `grow-your-christmas-dinner`, `blog/[slug]`, etc.). Harmless but cargo-cult — worth a single bulk strip pass rather than one-by-one, and worth remembering not to add it to new pages going forward.

### Small/no-action note
`next.config.ts` permanently redirects `/kit → /guides`, but `src/app/kit/page.tsx` still carries its own full metadata block (title/description/keywords) that can never be crawled since the redirect fires first — dead code, not an SEO bug, worth a cleanup pass whenever that file is next touched. Canonical tags, by contrast, are in good shape: consistent relative `alternates.canonical` resolved against `metadataBase` (`src/app/layout.tsx:54`) across every indexable template, no missing/wrong-domain canonicals found. Headings are clean too — every crop/variety/city/guide template renders exactly one H1, and the "heading stutter" pattern flagged in `docs/ANTI_PATTERNS.md` was not found live on `/crops`, `/sow` or `/guides` (only in nav link labels, which don't count).

This is exactly the kind of question a GSC connection would resolve in one pull instead of guesswork.

It's a seasonal page that won't earn its keep in July regardless of links — worth a note to link it from one seasonal guide or the homepage as the page comes into season (autumn/Christmas), not now.

### Apparent indexing (web search, approximate)

`site:` searches on this domain returned inconsistent results (the search tool didn't reliably respect the `site:` operator — even a bare `site:whattosow.co.uk` came back empty), so exact-phrase searches without the operator were used instead as a cross-check. Reliable positive signal: the **homepage, `/frost-map`, `/calendar`, `/crops/peas`, and `/sow-in/leicester`** all surfaced naturally for relevant queries, which is a decent sign core pages and at least one crop and one city page are indexed and being matched to real searches.

No signal either way (didn't surface, but the method is too weak to call this "not indexed") for the site's **newest pages**, all published within the last few weeks: `/guides/sow-now-eat-all-winter` (15 Jul), `/guides/watering-while-away` (5 Jul), `/guides/dealing-with-the-glut` (5 Jul), `/grow-your-christmas-dinner` (7 Jul), and `/blight-watch` (competing hard against the long-established `blightwatch.co.uk`/BlightSpy brand for its own name). **Recommendation:** once Search Console is connected, request-indexing these five directly rather than waiting on organic discovery — that's a two-minute job with real data and pure guesswork without it.

Worth flagging that this isn't a fresh idea — it's already an approved-but-unbuilt card in the ideas pipeline (`docs/dreams/wisdom.md` §5, approved 11 Jul with an explicit ask for "lots of photos and videos"), so the SEO case and the editorial case for building it now point the same way, with the window closing in under two weeks.
