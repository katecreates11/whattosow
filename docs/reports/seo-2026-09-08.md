## FIX NOW

### 1. `/privacy` is still indexable but still missing from the sitemap — one-line fix, unfixed for 8+ days
Confirmed again this run: `src/app/privacy/page.tsx` has a real title, description, no `noindex`, but
no entry in `src/app/sitemap.ts`. **Fix** (unchanged from last week):
```ts
{ url: `${baseUrl}/privacy`, lastModified: new Date("2026-04-02"), changeFrequency: "yearly", priority: 0.3 },
```

### 2. `/grow-your-christmas-dinner` is still a true orphan — and the seasonal window is opening now
Re-checked by grepping every file in `src/app` and `src/components` for the string
`grow-your-christmas-dinner`: it appears only inside its own page file, the sitemap entry, and the
new seasonal-route-policy list (which controls revalidation cadence, not linking). **Zero internal
links anywhere.** This is the single highest-value fix on the list right now: the page is a
countdown-format page, September is exactly when "growing your own Christmas dinner" search interest
starts (competitor pages — Suttons, Kitchen Garden, Two Wests & Elliott — are already live and
ranking for this), and a plain-text web search for the page today still surfaces none of
whattosow.co.uk while a baseline check on `/crops/lettuce` confirms the site's well-linked pages do
surface fine. Zero internal links is a plausible cause. **Fix:** add a link from
`/guides/growing-brassicas` (sprouts), `/guides/preparing-your-plot-for-winter`, and
`/guides/autumn-planting-garlic-onions`, plus a seasonal homepage/footer nudge as the countdown
becomes meaningful (roughly from now through December).

### 3. `/still-time` is correctly unlinked — but that just confirms the redirect is overdue
Also zero internal links, and this time I can show it's deliberate: a new test,
`src/app/search-console-readiness.test.ts:121`, explicitly asserts the footer does **not** contain
`href="/still-time"`. So this isn't an accidental orphan — the site has already decided not to link
it, per `docs/CUT_LIST.md`'s plan to demote it to a redirect into `/sow`'s amber tags. Right now the
page is doing neither job (not linked, not redirected). Not a new finding, just confirmation the
already-approved cut is the actual fix, not a linking fix.
