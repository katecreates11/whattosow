## FIX NOW

### 1. Meta descriptions over 160 characters — the single biggest lever, now scoped site-wide
Previously scoped as a `/guides`-only problem (26 of 33). It isn't: **34 of 58 pages with a
static description exceed 160 characters**, including pages outside `/guides` entirely —
`src/app/bed-planner/page.tsx` (215 chars), `src/app/about/page.tsx` (177), `src/app/sow/page.tsx`
(171 — sitemap priority 0.9), `src/app/longest-day/page.tsx:15` (168),
`src/app/grow-your-christmas-dinner/page.tsx:12` (168), `src/app/frost-map/page.tsx:10` (164).
Worst offenders unchanged: `guides/autumn-planting-garlic-onions/page.tsx:33` (233 chars — the
single worst on the site), `guides/watering-while-away/page.tsx:873` (214),
`guides/growing-root-vegetables/page.tsx:369` (213). **Dynamic templates also overflow for
longer names**: the crop-page template (`src/app/crops/[slug]/page.tsx:431-433`) hits 176 chars
for "tomatoes" and 162 for "Brussels sprouts" (roughly half of the 48 crops will overflow
depending on name length); the city-page template (`src/app/sow-in/[city]/page.tsx:50`) hits 166
chars for "Stoke-on-Trent, Staffordshire." **Fix:** trim each to end on a full sentence around
150 characters — genuinely a single afternoon across the ~34 static files plus two template
tweaks, not 34 separate decisions.

### 2. Title length — same root cause, still open
**18 of 33 static guide titles exceed 60 characters** (worst: `growing-root-vegetables` 79 chars,
`growing-squash-pumpkins-courgettes` 78, `growing-brassicas` 78, `tomato-blight` 76), all 17
`/guides/companion-planting/[topic]` pages (65–76 chars, `src/data/companion-topics.ts`), and
**3 of the biggest crop pages — tomatoes (77 chars), carrots (76), courgettes (79)** —
`src/app/crops/[slug]/page.tsx:427-430`, all from one shared template string padding an
already-descriptive title with "| What To Sow". Same fix shape as #1: drop either the parenthetical
qualifier or the site-name suffix, not both.

### 3. `/grow-your-christmas-dinner` — still a true orphan, now genuinely last-call
Re-confirmed by grepping every file in `src/`: `christmas-dinner` appears only in the page's own
file, `src/app/sitemap.ts:94` and a revalidation-cadence line in
`src/lib/seasonal-route-policy.ts:15` — zero inbound links from anywhere else on the site, and it
still doesn't surface in search (checked again this week). Today is 22 September; the Nov/Dec
search window is 8–9 weeks out, right at the edge of the lead time Google needs to crawl, index
and rank a newly-linked page. **Fix (unchanged, now urgent):** link it from
`/guides/growing-brassicas` (sprouts), `/guides/preparing-your-plot-for-winter` and
`/guides/autumn-planting-garlic-onions`, plus a homepage/footer seasonal nudge from now through
December — and request-indexing the moment it's linked.

### 4. `/kit`, `/my-plot`, `/my-garden`, `/lucky-dip` are unreachable dead code carrying full SEO metadata
New this week: all four routes are permanently redirected before they ever render
(`next.config.ts:6-11` — `/kit` → `/guides` 301; the other three → `/` 307, "taken down
2026-07-14"), yet all four `page.tsx` files still ship a complete `metadata` object (title,
description, `keywords` array, OpenGraph, canonical, and — for `/kit` — JSON-LD). None of it can
ever be seen by a crawler; a request to any of these four URLs never reaches the file. This isn't
an indexing risk, just landmine housekeeping: worth deleting the dead page files (or at minimum
their metadata blocks) rather than leaving four fully-dressed pages that can never serve. This
also resolves the `/kit` "wrong canonical" item flagged in previous reports — it was never wrong
relative to the redirect, just dead weight either way.

### 5. Structured data gaps on the two most-trafficked hub pages
Coverage is good almost everywhere else (crop pages carry `HowTo`+`FAQPage`, most guides carry
`Article`+`FAQPage`+`BreadcrumbList`, blog posts are richest of all). But:
- **`src/app/sow/page.tsx`** and **`src/app/crops/page.tsx`** — sitemap priority 0.9, the two
  biggest hub pages on the site — have **no JSON-LD at all**, not even `BreadcrumbList` or an
  `ItemList` for the crops/weeks they list.
- **`src/app/sow/[month]/page.tsx`** (12 evergreen pages) has only `BreadcrumbList`, no `Article`,
  despite being genuine long-form content per month.
- **7 guides** (`beginners`, `crop-rotation`, `growing-fruit`, `pests`, `seed-starting`, `soil`,
  `watering`) have `FAQPage`+`Breadcrumb` but no `Article`/publisher schema, unlike the other 26.
- **All 181 variety pages** carry only `BreadcrumbList` — no `Product`/`Offer` schema, despite
  being the site's designated buy-intent tier with real seed-supplier links.

### 6. `/privacy` is still indexable but still missing from the sitemap
Unchanged for the fourth week running. Confirmed again: `src/app/privacy/page.tsx` has a real
title/description, no noindex, and is linked from the footer — it just isn't in
`src/app/sitemap.ts` (confirmed via direct grep, zero matches). One-line fix:
```ts
{ url: `${baseUrl}/privacy`, lastModified: new Date("2026-04-02"), changeFrequency: "yearly", priority: 0.3 },
```

### 7. `/sow-in/[city]` titles still change every hour for no reason
Unchanged: `src/app/sow-in/[city]/page.tsx:49` bakes the current month and year into the
`&lt;title&gt;` itself, and the page revalidates hourly (`export const revalidate = 3600`, line
23). Google sees a different title for the same URL every calendar month, for all 50 cities, even
though the crop list already updates without a title change. One-line fix: drop month/year from
the `&lt;title&gt;`, keep it in the on-page copy.

### 8. Housekeeping — bundle into the pass above
- **57 files still carry a legacy `keywords` meta array** (confirmed again via direct grep,
  identical count to last week) — `src/app/layout.tsx`, all 33 guides, all 17 companion-planting
  topics, 27 editorial posts, and most core route pages. CUT_LIST's "stop adding these" rule has
  not been applied retroactively anywhere. Delete while editing these files for #1/#2 anyway.
- **Homepage still renders two `&lt;h1&gt;` elements** at once —
  `src/app/page.tsx:269` (`sm:hidden`, mobile) and `:299` (`hidden sm:flex`, desktop), identical
  text, CSS-toggled only. Both exist in the server-rendered HTML simultaneously — a crawler sees
  markup, not the media query. One `&lt;h1&gt;` with responsive styling fixes it.
- **New this week — `/guides` and `/crops` hub pages have an H1 that doesn't match their own
  title/meta.** `src/app/guides/page.tsx` — `metadata.title` (line 535) is "Growing Guides — What
  To Sow" but the actual `&lt;h1&gt;` (lines 403–405) is the tagline "How to grow it well," with
  none of the target keywords. Same pattern on `/crops`: title "Vegetable &amp; Fruit Growing
  Guides — Every Crop" vs. H1 "The crops" (`src/app/crops/page.tsx:24-26`). Low effort, real
  relevance-signal gap — the H1 is one of the strongest on-page ranking signals and currently
  carries none of the query terms the title already targets.
- **All 181 variety pages still duplicate their parent crop page's text word-for-word**
  (`src/app/crops/[slug]/page.tsx:854` and `:865` vs. `src/app/crops/[slug]/[variety]/page.tsx:125`
  and `:147`) — unchanged since first flagged. This is Kate's call per CUT_LIST §4's ⛔ marker
  (content removal/restructure either way): either stop rendering full variety text on the parent
  crop page (teaser + link instead), or treat it as further evidence toward pruning the cluster.
